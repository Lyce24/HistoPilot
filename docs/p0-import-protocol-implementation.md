# P0.0 / P0.1 / P0.2 implementation handoff

New protocols use the five [version-3 split strategies](split-strategies.md), with explicit training and final test selections. K-fold CV within training is the default; early stopping uses a training percentage or a fixed validation set. Earlier behavior remains available in saved version-1 and version-2 protocols. Dataset import and durable storage are shared across versions.

The real local workflow now supports **create/load experiment → inspect metadata → map identities and attributes → preview → freeze dataset → attach existing features → define target and patient split → preview → freeze protocol → reload**. The synthetic CRC demo remains separate. No training or extraction is launched by these operations.

## UI and scientific choices

**Dataset workspace** accepts a CSV/XLSX server file path or small browser upload, worksheet selection, an optional slide folder and optional patient crosswalk/table. The user maps existing headers to `Slide_ID` and `Patient_ID`. Source strings, leading zeros and dotted identifiers are preserved; `De ID` never automatically becomes a verified patient identifier. Each scalar attribute has an editable key, source column, slide/patient owner and declared type. Missing tokens and ordered categories are explicit. A single combined table or separate slide/patient sources work through the same canonical records.

The guided import uses **Choose files → Map columns → Preview & freeze**, with only the current stage displayed. **New import** starts at the file stage. **Read file & show columns** explains the first read and displays row/column counts; **Continue to column mapping** follows the slide-folder options. Back controls let users revisit files or mappings, preserving their draft choices. Changes invalidate the previous preview before another freeze. Each attribute shows up to four common source values, distinct-value counts and empty-cell counts from the complete parsed source. Examples preserve spelling and case; they do not choose a type, recode labels or establish patient identities. Smaller screens show labeled attribute cards instead of hiding fields offscreen. A failed reread clears old examples.

**Add patient IDs or attributes from another file** includes hover, keyboard-focus and tap help. A crosswalk joins `Slide_ID` to verified `Patient_ID`; a patient attribute table joins patient attributes onto an already mapped `Patient_ID` in the main table. The help includes an illustrative many-slides-to-one-patient example and explains when a combined table makes the extra file unnecessary. Preview labels its count **Slides to include**; only freezing creates the fixed dataset version.

If any included slides still have null patient IDs, continuing from mapping asks the user to confirm **Patient ID unresolved, fallback to Slide ID**, or go back to change the mapping. Confirmation persists `patientIdFallback: "slide_id"` in the import intent. Only missing patient IDs are filled, after genuine patient joins have completed. Each affected record has `patientId` equal to its `slideId` and `patientIdSource: "slide_fallback"`; existing patient IDs and their grouping are preserved. Other new records identify their source as `source`, `crosswalk` or `unresolved`. The setting, record markers, warning and separate counts survive freeze and reopening. Changing the identity inputs requires a fresh review of that choice.

Fallback permits protocol preparation with one group per unresolved slide. It does not verify biological patient independence: two slides from one unknown patient could enter different sets. The UI therefore distinguishes known patients, fallback slide groups and total groups. A fallback slide ID that collides with a supplied patient ID blocks freezing rather than merging them. Old frozen datasets are not rewritten; revise and freeze a new version to opt into fallback or add a patient crosswalk, then attach features to that exact new dataset version. The API can still retain unresolved IDs with the default `patientIdFallback: "unresolved"`; those rows block protocol assignment until explicitly resolved or acknowledged in a revised dataset.

Preview reports included/excluded metadata rows, matched/unmatched files, duplicate IDs, ambiguous matches, patient conflicts and unresolved links. A complete bounded scanner is independent of the 200-entry folder picker. Users can deliberately retain records without slide files for feature-only workflows. A frozen dataset stores canonical records, dictionary, inventory, exclusions, source metadata bytes, mapping and hashes. A later patient crosswalk creates a new version, optionally linked to its parent.

Frozen exploration applies search and attribute filters on the server before pagination. Categorical/ordered distributions, numeric histograms, missingness and categorical cross-tabs use that same population. Patient-owned attributes count distinct mapped groups and identify when fallback groups are present; slide attributes count slide rows. Verified-patient and fallback counts remain separate. OR applies within selected category values, AND across fields on the same slide. Unlinked slides remain visible separately. Preview exploration is explicitly a displayed-row sample; frozen exploration covers the full dataset.

**PFM & features** attaches an existing HDF5 directory to a particular frozen dataset. Matching uses the complete filename stem plus an optional literal suffix removal; it never truncates at the first dot. Inspection reports coverage, orphan files, duplicate matches, dimensions, dtype and patch counts. It requires nonempty floating-point `features[N,D]` and integer `coords[N,2]` with matching row counts and rejects external/virtual HDF5 storage. The selected feature binding is immutable and can be assigned to a protocol. The encoder selection is a declaration, not authenticated provenance.

**Target & split / MIL experiments** exposes binary/multiclass targets, ordered classes, explicit raw-label mappings and a binary positive class. Missing/unmapped labels block by default; exclusions must be selected deliberately. Scalar covariates are opt-in. IDs, split columns, target aliases and observed one-to-one target encodings cannot become predictors.

Selecting a target shows its declared format, typical raw values and a distribution across the frozen dataset. **Choose slides and optional extra inputs** explains that the cohort is the set of slides used in the experiment. It shows slide, known-patient and fallback-group counts even when there are no eligibility rules. **Extra spreadsheet inputs (optional)** explains covariates with examples such as age; these are additional scalar model inputs, separate from image embeddings and the prediction label. An image-only experiment can leave them empty.

Eligibility and partition editors show the selected field's format and common source values beside the condition. Live statistics come from the complete frozen dataset through the read-only `/protocols/explore` route; they do not require finished label mappings, a feature binding or a saved protocol draft. Each partition displays direct rule matches, counts after expanding to eligible slides in each group, and up to five example rows. A bar compares its slide count with the eligible cohort. The eligible target distribution counts raw labels before missing/unmapped-label exclusion policies, so the final **Preview & preflight** can have a smaller included population. Invalid conditions clear affected counts and show a finding; previous or unfiltered totals are not presented as successful matches.

Eligibility and fixed train/validation/test rules use typed conditions: exact equality/inequality, set membership, numeric comparisons, existence and timeout-bounded regex. Expressions are never evaluated as Python. Conditions within a rule all apply to the same slide. If an eligible slide satisfies a fixed-partition rule, all included slides of its group receive the same partition. Competing rules that select different slides of the same patient block as overlapping patient rules. A fallback slide is its own group. Eligibility does not silently include otherwise excluded slides. Live feedback and final preview share the evaluator, including the cumulative regex time budget; invalid numeric source values block numeric comparisons rather than silently matching or disappearing.

Supported split modes:

- **Choose sets with rules:** the default for new UI protocols. Test and validation rules reserve groups. Validation is optional; an empty validation rule creates no validation set. Empty training rules assign every remaining eligible group outside test and validation to training. Explicit training rules must account for every remaining group; unassigned groups block freezing. Overlaps block in all cases. This mode generates one assignment at fold `0` per selected seed; multiple seeds reuse the same rule-determined sets with a visible warning. The UI hides generation controls for this mode.
- **Patient k-fold:** 2–10 validation folds and 1–10 distinct uint32 split seeds. Fixed train/val/test assignments remain fixed; remaining groups rotate through validation folds. No hidden test holdout is added.
- **Patient holdout:** train/val/test proportions sum to one and apply to groups remaining after fixed rules. Class-stratified rounding and minimum constraints can change exact proportions; the preview displays actual counts.
- **Imported assignments:** explicitly map partition values and/or fold values. Held-out fold labels require an explicit mapping. Patient disagreement, missing/unknown assignments, conflicting rules and absent declared folds block freezing. Imported memberships are reused across seeds with a visible warning.

The split algorithm is versioned (`histopilot-patient-stratification-v1`) and orders grouping identities using SHA-256 with the seed and class for generated splits. Exact memberships and identity-source markers are persisted for every seed/fold. Reordering input records or requested seeds does not change assignments. Constraints check minimum groups per partition and per class in every required partition. A group is a known patient or an acknowledged fallback slide; satisfying a minimum does not establish independence for fallback slides. In rules mode, training is required and validation/test are required only when their rules are configured. Existing generated and imported split behavior remains unchanged. Seeds here are **split seeds**; training randomness belongs to the later run specification.

For the Bladder example, map `De ID` to `Slide_ID`, keep the `WHO 2022` and `WHO 1973` source values, and either provide a patient crosswalk or confirm fallback. Select `WHO 2022` as the binary target and `high` as the positive class. In rules mode, add `WHO 1973 equals 2` (or regex `^2$`) to Test and leave Training and Validation rules empty. With all 138 slides using fallback, the current CSV selects 76 test slides and the remaining 62 training slides, with zero known patients and no validation set. With genuine patient IDs, those counts can change after patient expansion; review the live counts and final preflight. This example is a preparation workflow, not a clinical validation claim.

## Persistence and preflight

Scientific SQLite schema 2 adds immutable configuration snapshots and publication receipts through an atomic additive schema-1 migration. Existing dataset artifact format remains version 1 and old files are not rewritten. A protocol publication commits checksummed JSON, retry receipt and frozen draft status in one FULL-sync transaction. Protocol identity excludes draft IDs/revisions; equivalent scientific specifications can reuse the same frozen configuration. Stale revisions and previews cannot publish. Repeating an identical operation returns its saved result.

Dataset import snapshots use the P0.0 staged-file publication/recovery path. Feature bindings and protocol manifests live in the same folder-owned database, so another service registry can reopen all of them. UI queries read persisted state, and editing a specification invalidates its displayed preview.

Protocol preview blocks unacknowledged unresolved patient identities, fallback-ID collisions, invalid labels, conflicting patient labels, leaking imported assignments, infeasible folds/partitions, overlapping rules, unassigned explicit-rule groups and missing selected-feature coverage. Acknowledged fallback emits a persistent warning instead of an unresolved-ID blocker. A frozen-protocol preflight verifies its dataset and rechecks selected feature files against saved headers and modification metadata. The project-scoped job route runs that preflight and submits no job: input blockers return 422; execution itself remains unavailable. Full content/provenance validation is still required before a real executor is introduced.

| Actual Bladder split readiness | Requires verified patient linkage or explicit fallback acknowledgement; label/rule/feature checks still apply and execution remains unavailable |

Temporary known-patient fixtures verify the complete API flow through import, feature attachment, grade-2 holdout, two seeds/two folds, freeze and reopening from a new registry. Tests cover row/process-order reproducibility, stale previews, unknown labels, patient leakage, source changes, regex timeout, migration rollback, atomic configuration interruption and the existing P0.0 crash-recovery suite.

Current bounded scope is 16 MiB per server metadata table, 256 KiB per inline upload, 20,000 source rows, 128 columns and 10,000 discovered file/directory entries. Overflow fails explicitly without freezing a partial inventory. Metadata scans are synchronous bounded CPU work; resumable large-scan workers remain a follow-up. Protocol previews cap membership work and serialized snapshot size; stored configurations are limited to 16 MiB.

Mixed-label patients currently block stratification even for slide-level targets; no majority label is chosen. Patient-owned attributes with inconsistent known values or mixed known/missing values require correction before freezing. Arbitrary multi-table joins, mixed-label stratification, complete tensor checksums/finite-value checks, verified extraction provenance, GPU execution and real results are subsequent work. Frozen external paths and header checks are not a claim that mutable source arrays are fully verified.
